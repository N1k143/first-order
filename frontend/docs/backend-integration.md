# Связь фронтенда с сервером

## Подтверждённый контракт

В `backend/services/catalog/cmd/api/main.go` зарегистрирован только `GET /health` с текстовым ответом `OK`. Frontend вызывает `/api/health`, а Next.js переписывает запрос на `${BACKEND_URL}/health` (по умолчанию `http://127.0.0.1:18080`).

Кнопка в настройках выполняет настоящий запрос. Если сервер не запущен, показывается ошибка подключения. В текущем окружении порт 18080 недоступен, а команда `go` и стандартные пути Go отсутствуют, поэтому проверка с запущенным Go-сервисом не выполнена. Браузерный тест проверяет интерфейс с перехваченным ответом `/api/health`; unit-тест проверяет транспорт. Это не подтверждение работы живого сервера.

## Предлагаемые, но пока не реализованные API

Следующие пути уже использует frontend-клиент в экспериментальном API-режиме. Они требуют согласования и реализации на бэкенде:

| Действие        | Путь                                                                              | Ожидаемые данные                                    |
| --------------- | --------------------------------------------------------------------------------- | --------------------------------------------------- |
| Поиск компаний  | `GET /companies?q=&city=&category=&status=&sort=&page=`                           | `Paged<Company>`                                    |
| Компания        | `GET /companies/:id`                                                              | `Company`                                           |
| Поиск заказов   | `GET /orders?q=&city=&min=&max=&status=`                                          | `Order[]`                                           |
| Заказ           | `GET /orders/:id`                                                                 | `Order`                                             |
| Отклик          | `POST /orders/:id/applications`                                                   | Создание отклика, проверка дублей и роли на сервере |
| Избранное       | `POST/DELETE /me/favorites/:id`                                                   | Изменение собственного избранного                   |
| Заметки         | `PATCH /me/contacts/:id`                                                          | Статус, заметка, дата                               |
| Исправление     | `POST /companies/:id/corrections`                                                 | Сообщение об ошибке                                 |
| Авторизация     | `POST /auth/login`, `/auth/register`                                              | Контракт сессии ещё не определён                    |
| Письма и пароль | `POST /auth/forgot-password`, `/auth/reset-password`, `/auth/resend-verification` | Серверная отправка и проверка одноразовых токенов   |

Модели находятся в `src/types/domain.ts`. `credentials: include` подготовлен для cookie-сессии, но серверной сессии сейчас нет. Cookies, CSRF, проверка роли, идентификация автора, валидация и ограничения запросов должны быть определены при реализации бэкенда; клиентские ограничения не являются авторизацией.

## Что пока работает только локально

Создание/предпросмотр/публикация заказов, выбор исполнителя, завершение заказа, редактирование профиля и портфолио, управление компанией, решения модератора. Для этих операций пока нет серверного адаптера: личные страницы в API-режиме показывают недоступность и не записывают демоданные.

Импорт каталога и приглашения участников намеренно показывают недоступность, а не имитируют загрузку или отправку письма. Информация об условиях и данных относится к демонстрации и не заменяет документы рабочего сервиса.
