# Поля профиля и предоставленная схема

Источник: схема таблиц и RLS, присланная владельцем проекта в этой задаче. Бэкенд и политики не изменялись.

| Таблица           | Редактируемые пользователем данные                                      | Служебные данные                                                       |
| ----------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `profiles`        | `name`, nullable `bio`, nullable `skills` (text), nullable `github_url` | `user_id`, `role`, nullable `is_moderator`, `created_at`, `updated_at` |
| `portfolio_items` | `title`, nullable `description`, nullable `project_url`                 | `id`, `developer_id`, `created_at`, `updated_at`                       |
| `company_members` | Нет операций записи в предоставленных политиках                         | `company_id`, `user_id`, `member_role`, `created_at`                   |

`src/types/database.ts` задаёт формы строк и явные типы разрешённых обновлений. `profileFields` и `portfolioFields` берут только пользовательские поля из формы, преобразуют пустые необязательные строки в `null` и не включают переданные извне идентификаторы, роли или флаги доступа. Модель интерфейса хранит навыки как список; при сохранении в БД это текстовое поле. Email относится к аккаунту авторизации, а не к предоставленной таблице `profiles`.

В присланной схеме нет полей фотографии, города и специализации. Аватар — дополнительное локальное поле демоверсии. Город и специализация остаются в существующих примерах данных, но не входят в редактор полей БД. Фото не отправляется на сервер и не загружается в Supabase Storage.

## Границы интеграции и RLS

Текущие формы сохраняют демонстрационные данные в браузере. Схема БД сама по себе не предоставляет URL проекта, конфигурацию сессии или реализованные API для записи. Серверное подключение не объявляется завершённым.

Предоставленная `profiles_update_own` проверяет владельца строки, но не ограничивает изменяемые столбцы. Перед подключением прямого обновления таблицы нужно отдельно ограничить запись `role` и `is_moderator` серверным механизмом или правами на столбцы. Отсутствие этих полей в форме и клиентский список разрешённых полей не заменяют серверную защиту.

`profiles_insert_own` разрешает вставку своей строки только с `role = 'developer'`; создание аккаунта компании требует отдельно определённого серверного сценария. Вход по роли в демоверсии меняет локальный сценарий; в рабочем сервисе роль и членство должны приходить из доверенной сессии.

Политики `portfolio_manage_own` связывают запись с `auth.uid()`. `developer_id` должен задаваться из сессии при создании работы, а не из произвольного поля формы. Для `company_members` предоставлена только политика SELECT; интерфейс не предлагает действующих операций изменения участников.
