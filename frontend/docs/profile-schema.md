# Поля профиля и серверный контракт

Редактор работает с Go API в режиме `api` и с отдельным локальным состоянием в режиме `demo`. Действующая схема описана миграциями `backend/migrations`; исходные таблицы и RLS использованы при составлении типов интерфейса.

| Таблица                    | Пользовательские операции                                                                           | Служебные данные                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `profiles.profiles`        | PATCH `name`, nullable `bio`, `skills` (text), `github_url`, `avatar_url`                           | `user_id`, `role`, `is_moderator`, даты                             |
| `profiles.portfolio_items` | Создание, чтение, PATCH и удаление; `title`, nullable `description`, `project_url`                  | `id`, `developer_id`, даты                                          |
| `profiles.company_members` | Владелец добавляет зарегистрированного пользователя по `user_id` с `member_role`, удаляет участника | Действующий пользователь берётся из сессии; последний owner защищён |

`src/types/database.ts` задаёт строки и явные типы разрешённых обновлений. `profileFields` и `portfolioFields` берут только пользовательские поля формы, преобразуют пустые необязательные строки в `null`, не включают роли, флаги доступа или ID автора. Backend независимо отвергает неизвестные и служебные поля. Отсутствующее поле в PATCH сохраняет прежнее значение, явный `null` очищает nullable-поле.

Навыки представлены списком в интерфейсе и текстом в БД. Полей города и специализации в таблице профиля нет; они не отправляются редактором. Email относится к Supabase Auth и меняется через `/auth/change-email` с подтверждением, а не через PATCH профиля.

## Аватар

Миграция `003_profile_avatar.sql` добавляет `avatar_url text`, если столбца ещё нет. `GET /me`, публичный профиль и PATCH возвращают это поле; compatibility API преобразует имя в `avatarUrl`.

Допускаются http(s)-ссылка до 2048 байт либо PNG/JPEG/WebP data URL с изображением до 256 КиБ после декодирования и размером до 2048×2048. Backend проверяет фактический формат и возможность декодирования. Внешнюю ссылку сервер не скачивает. Data URL сохраняется в БД, удаление передаёт `null`; отдельный Supabase Storage или другой файловый сервис не требуется.

## Права доступа

Браузер обращается к Go API. Миграция `002` закрывает прямой доступ ролей `anon`/`authenticated` к прикладным таблицам; исходные RLS-политики не являются единственной защитой формы. Backend получает автора из проверенной сессии и проверяет владельца портфолио, членство и роль владельца компании. Пользователь не может изменить платформенную роль или `is_moderator` через профиль.

Регистрация представителя создаёт новую скрытую компанию с membership `owner`. Совпадение названия с существующей карточкой не даёт права ею управлять; принадлежность подтверждается отдельно. Добавление участника по UUID не отправляет email-приглашение.
