# Состояние переноса FirstOrder

Срез: 19 ноября 2026 года. Источник дизайна: https://www.figma.com/design/eEBIHk6nceh158jZmZxCPe/FirstOrder

## Полученные материалы

- Главная, узел `8:2`: полный design context и скриншот; Golos Text поставляется локально через Fontsource.
- Desktop, страница `0:1`: структура узлов; дополнительно получен пользовательский экспорт 36 экранов PNG/SVG.
- Mobile: пользовательский экспорт 12 экранов PNG/SVG.
- UI kit: пользовательский экспорт PNG/SVG.

После ограничения чтения Figma MCP перенос продолжился по полученным экспортам.

## Реализованный интерфейс

Next.js App Router, TypeScript, CSS Modules, общие токены, шапка/подвал и карточки. Доступны:

- главная;
- каталог компаний с поиском и фильтрами в URL;
- карточка компании, контакты и отправка исправления;
- список заказов, страница заказа и отправка отклика;
- кабинет компании: список заказов, создание черновика, публикация, закрытие, просмотр откликов, подтверждение выбора исполнителя и завершение;
- личный список откликов разработчика с решениями и отзывом поданного отклика;
- выбор роли, регистрация разработчика/представителя, вход;
- восстановление и смена пароля, повторная отправка подтверждения email;
- `/auth/callback` для завершения подтверждения или восстановления через Supabase Auth;
- личный обзор, профиль/аватар/портфолио, избранное и история контактов с реальным сохранением в API-режиме;
- настройки email/пароля, обзор и редактирование компании, управление участниками, редактирование и предпросмотр заказа;
- демонстрационные экраны модерации, импорта и журнала, справочные страницы.

## Интеграция с сервером

Backend больше не ограничен health-check: реализованы маршруты канонического API и серверные операции авторизации. Инструкции запуска и ограничения backend приведены в [backend/README.md](../../backend/README.md).

Frontend по умолчанию остаётся в демонстрационном режиме. `NEXT_PUBLIC_DATA_MODE=api` явно включает реальные запросы; после изменения необходим перезапуск dev-сервера или новая production-сборка. В API-режиме начальное состояние пустое, `/me` определяет пользователя, а избранное, контакты, портфолио, отклики и заказы загружаются с backend. Успешные мутации обновляют состояние и ресурсы; ошибки не заменяются демонстрационными записями.

`BACKEND_URL` задаёт серверу Next.js адрес Go API. Прокси отдельно сохраняет `/api/v1/*` для канонического контракта, поддерживает `/api/*` для текущих совместимых маршрутов и Auth и передаёт `/health`/`/ready` в backend.

Cookies сессии — HttpOnly. Клиент обновляет истёкшую сессию через один общий refresh для одновременных запросов и делает не более одного повтора после `401`. Пароли и токены сессии не сохраняются в localStorage. Callback обменивает fragment-токены либо `token_hash`/`type` на серверную сессию, очищает адресную строку и направляет восстановление на `/reset-password`, остальные подтверждения — в `/workspace` для компании, `/applications` для разработчика или `/companies` для модератора. Для реальных писем необходимо настроить Supabase Auth, SMTP и разрешённый callback URL на стороне сервера.

## Оставшийся объём

- Модерация, импорт и журнал модерации остаются демонстрационными экранами с явным ограничением в API-режиме. Профиль, портфолио, избранное, контакты, настройки, компания и участники подключены к серверу.
- Участники добавляются по ID уже зарегистрированного пользователя; отправка email-приглашений не реализована.
- Аватар сохраняется в nullable `avatar_url` после миграции `003`; разрешены http(s)-ссылка или проверенный data URL PNG/JPEG/WebP до 256 КиБ, максимум 2048×2048. Внешнее файловое хранилище не подключалось.
- Смена email остаётся ожидающей до подтверждения Supabase; безопасная смена может потребовать две ссылки. Настройки не подменяют адрес до подтверждения.
- Шапка сохраняет аватар и мобильную навигацию, учитывает режим данных и доступный кабинет. Серверный выход очищает сессию.
- Главная показывает открытый заказ из текущего состояния; в режиме API примеры не подставляются.
- Мобильная адаптация главной требует окончательной сверки с полученными макетами.
- Для существующей компании право представительства подтверждается отдельно; регистрация не даёт произвольного доступа к найденной карточке.

## Выполненные проверки

До объединения веток TypeScript, ESLint, production-сборка Next.js 16.4.6 и 7 тестов API-клиента прошли. Тесты проверяют health-proxy, HTTP-ошибки без подстановки fixtures, пустые ответы, некорректный JSON, запрет внешних адресов, общий refresh и ограничение повторов. Сгенерированный routes manifest подтверждает приоритет канонического `/api/v1/*` перед общим rewrite.

Рабочий сайт до объединения веток опубликован в API-режиме, Supabase и Gmail SMTP подключены. Браузерный сценарий сначала прошёл с заменёнными ответами API, затем на рабочем сайте и PostgreSQL. Проверены также refresh и выход. В финальном прогоне два аккаунта зарегистрированы через публичную форму, оба письма получены и оба адреса подтверждены настоящими ссылками. После подтверждения production Playwright успешно завершил за 12,1 с сценарий: вход компании → создание черновика → публикация → отклик разработчика → выбор исполнителя → отображение принятого отклика. Подтверждение email оставалось обязательным; административное подтверждение не использовалось.

Все записи финального тестового прогона и тестовые пароли удалены; повторная проверка показала 0 оставшихся тестовых записей. Доказательства, состав очистки и подробности развёртывания — в [deploy/README.md](../../deploy/README.md). `npm ci` завершился успешно; на дату установки проверка зависимостей сообщила 0 уязвимостей.

После объединения веток выполнены TypeScript, ESLint, сборки demo/API, 17 модульных тестов и 20 браузерных тестов деморежима. Проверки объединения выполняются в отдельной рабочей копии.

Браузерная проверка API-режима с контролируемыми ответами также прошла: гостевой доступ, вход/refresh/выход, создание и редактирование черновика с пустыми бюджетом и сроком, предпросмотр, публикация, отклик, выбор исполнителя и отправка исправления компании. Локальные демонстрационные данные в API-режиме не сохранялись. Эта проверка не отправляет письма и не меняет рабочую базу.

Для подключения дополнительных разделов полный backend suite с race detector прошёл на отдельной PostgreSQL 17 после миграций 001–003. Проверены сохранение/чтение/удаление аватара, запрет недопустимых изображений и повышения роли, compatibility-массив категорий, смена email и пароля через контролируемый Auth. Тестовый контейнер удалён. Эта проверка не отправляла письма и не меняла рабочую БД; статус публикации обновления фиксируется отдельно в deploy/README.md.
