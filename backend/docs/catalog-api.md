# Рабочий каталог компаний: контракт и подготовка данных

## Публичный API

`GET /api/v1/companies`: стандартный список `{items,total,page,limit}`. Поиск `q` проверяет название, адрес, телефон и email. Фильтры: `city`, `category_id`, `category`, `website_status` (`found`, `not_found`, `needs_review`); `sort`, `page`, `limit` остаются совместимыми с существующим контрактом. Без сессии выдаются только опубликованные компании. `visibility=hidden/all` доступен только модератору.

`GET /api/v1/companies/{id}` возвращает одну компанию. Скрытая компания не видна гостю; владелец/представитель видит свою, модератор — любую.

К существующим полям компании добавлены:

```json
{
  "phone": "+77011112233; +77172223344",
  "phones": ["+77011112233", "+77172223344"],
  "has_contacts": true,
  "sources": [{
    "source": "osm_astana",
    "source_url": "https://www.openstreetmap.org/node/123",
    "attribution": "© OpenStreetMap contributors · ODbL 1.0 · https://www.openstreetmap.org/copyright",
    "license": "ODbL-1.0",
    "license_url": "https://www.openstreetmap.org/copyright",
    "reviewed_at": "2026-11-26T10:00:00Z"
  }]
}
```

`phone` сохраняет прежний строковый контракт; для нескольких отдельных кнопок звонка использовать `phones`. Источники содержат только публичные сведения, без исходных tags, черновиков, внутренних доказательств и ID модератора. У независимых вручную созданных карточек без импортированного источника `sources=[]`.

Ответы с OSM-источниками также содержат `Link: <https://www.openstreetmap.org/copyright>; rel="license"` и `X-Data-Attribution: OpenStreetMap contributors; ODbL-1.0`.

### Фильтры с количеством компаний

`GET /api/v1/catalog/filters` — публичный маршрут:

```json
{
  "cities": [{"city":"Астана","total":30}],
  "categories": [{"id":"category-uuid","name":"Автоуслуги","total":3}],
  "website_statuses": [{"website_status":"found","total":8}],
  "attribution":"© OpenStreetMap contributors · ODbL 1.0 · https://www.openstreetmap.org/copyright",
  "license_url":"https://www.openstreetmap.org/copyright"
}
```

Числа в примере условные. Счётчики глобальные, не зависят от выбранного поиска и учитывают только опубликованные компании. Категории без опубликованных компаний не возвращаются. При отсутствии публичных OSM-карточек поля атрибуции равны `null`. Административный полный справочник категорий остаётся доступен через `/api/v1/categories`.

### Что нужно от фронтенда

- Показывать источник и `© OpenStreetMap contributors` со ссылкой на `license_url` рядом с каталогом или в ожидаемом месте атрибуции; HTTP-заголовки не заменяют видимую атрибуцию в интерфейсе. [Правила атрибуции OSM](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines).
- `found` означает найденный сайт с сохранёнными доказательствами; `needs_review` — недостаточно сведений, не отсутствие сайта. Отсутствующий адрес/email/телефон отображать как неизвестный, не подставлять фиктивные значения.
- Использовать новый endpoint фильтров для категорий с количеством компаний. Фронтенд в этой итерации не меняется.

## Подготовка первых компаний

Из каталога `backend` с закрытым `DATABASE_URL`:

```sh
go run ./cmd/prepare-catalog --report=/tmp/catalog-preview.json
go run ./cmd/prepare-catalog --apply --report=/tmp/catalog-hidden.json
# Либо создать и сразу опубликовать прошедшие отбор карточки:
go run ./cmd/prepare-catalog --apply --publish --report=/tmp/catalog-release.json
```

Нужна миграция `006_operator_catalog_audit.sql` после 001–005. Файлы отчётов создаются с правами 0600, существующий файл не перезаписывается. Выгрузки и персональные настройки не добавлять в Git.

Команда обрабатывает до 100 ожидающих OSM-кандидатов. Для отбора нужны: название, город Астана, исходная ссылка OSM, известная категория и хотя бы один полноценный телефон, корректный email или подтверждённый website URL. Телефоны приводятся к `+7` и десяти последующим цифрам; короткий код сам по себе не считается достаточным контактом. Приведение формата не доказывает, что телефон сейчас обслуживается. Исходные данные сохраняются в кандидате.

Госорганы, дипломатические и политические организации, НКО/коммунальные учреждения не включаются автоматически в коммерческий каталог. Неизвестные категории, отсутствие контактов, возможные дубли и карточки с ручным черновиком остаются в очереди для модератора. Никакие исходные записи не удаляются. Политика — ограниченный отбор пилота, не универсальная классификация реестра юрлиц.

Повторный запуск не создаёт заново уже одобренные компании и не изменяет чужие существующие карточки. `--apply` без `--publish` создаёт скрытые карточки; их последующая публикация выполняется существующим API модератора. Команда без `--apply` только показывает предварительный отбор; итог может измениться из-за появления дублей или решения другого оператора.

Сравнение телефонов для дублей проверяет любой номер в списке, игнорируя разделители и разницу между `8` и `+7`. Совпадение — повод для ручной проверки, а не автоматического слияния разных филиалов.

## Аудит и права

Операторская команда не создаёт Auth-аккаунтов и не назначает модераторов. В историях каталога и кандидатов у таких событий `actor_type=operator`, `moderator_id=null`. У пользовательских действий `actor_type=moderator`. Для старых клиентов добавление поля обратно совместимо; `moderator_id` в истории каталога теперь nullable. Не приписывать операторские действия конкретному пользователю.

Обработка выполняется одной транзакцией и использует блокировки того же порядка, что кабинет модератора. Правки владельцев, memberships, заказы, видимость существующих компаний и уже рассмотренные источники не меняются. При неуспехе перепроверить состояние БД перед повтором; отчёт содержит только относящиеся к запуску ID и причины отбора.
