# Поиск и фильтры каталога

Требуется миграция `010_catalog_search.sql`. Она устанавливает [pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html), добавляет GIN-индексы для поискового выражения компании и названия категории, а также B-tree для нормализованного города. Если pg_trgm уже установлен, его схема не меняется. В API не добавляются служебные поисковые поля.

`GET /api/v1/companies?q=кофеня&city=Астана&website_status=needs_review&sort=relevance&page=1&limit=20`

Поиск охватывает название, адрес, город, телефон, email и сферу бизнеса. Регистр, повторные пробелы, разделители и различие е/ё не влияют на совпадение. Все слова запроса обязательны, но могут находиться в разных полях; порядок слов не ограничивает поиск. До 240 символов и 12 различных слов. Запрос из одних знаков возвращает пустую выборку; `%` и `_` не являются поисковыми масками.

Для слов от четырёх символов применяется словное триграммное сопоставление с порогом 0.4. Для четырёхсимвольных слов дополнительно требуется сходство не менее 0.5, чтобы короткие адреса не давали слишком много посторонних совпадений. Фрагменты до трёх символов и числовые контакты ищутся буквально. Номер можно вводить без форматирования. Поиск не выполняет транслитерацию, перевод или исправление раскладки клавиатуры.

При наличии q сортировка по умолчанию — релевантность: точное название выше начала названия, затем совпадения внутри названия и похожие слова; название имеет больший вес, чем категория и контакты. Можно явно выбрать `sort=relevance`, `updated`, `name`, `name_desc`, `newest` или `oldest`. Без q relevance соответствует updated. Стабильный последний ключ id сохраняет порядок страниц при равных оценках.

Фильтры `category_id`, `category`, `city`, `website_status`, `visibility` всегда объединяются с поиском через AND. Категория и статус остаются точными ограничениями. Город сравнивается после нормализации регистра, пробелов, разделителей и е/ё; это не поиск похожего города. Скрытые компании по-прежнему недоступны гостям и обычным пользователям. Поиск не меняет бизнес-статусы и не утверждает отсутствие сайта.

Количество и элементы страницы читаются в одном read-only repeatable-read снимке. Порог pg_trgm задаётся через SET LOCAL внутри транзакции и не остаётся на соединении из пула. Все пользовательские значения передаются параметрами. Совпадения по компании и категории объединяются в набор ID до применения внешних ограничений видимости; UNION не дублирует карточку, совпавшую по нескольким полям.

Проверки EXPLAIN подтверждают, что итоговый запрос допускает использование обоих GIN-индексов. В этих тестах принудительно выбираются bitmap-планы; на маленьком рабочем каталоге PostgreSQL вправе выбрать последовательное чтение или другой индекс, если считает это дешевле. Это проверка применимости индексов, не обещание определённого времени ответа.

Интерфейс `/companies` сохраняет сочетание фильтров при быстрых переключениях и сбрасывает страницу при изменении выборки. Поддерживаются ссылки с website_status: они переводятся в используемый интерфейсом status; явный status, включая пустой, имеет приоритет. Категория из старой ссылки category подсвечивается по имени. В мобильном окне один выбор города и доступна сортировка. Параметры сохраняются при обновлении страницы.
