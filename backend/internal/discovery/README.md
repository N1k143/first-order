# Сбор компаний Астаны

Оператор запускает ограниченный сбор OpenStreetMap через Overpass. Запрос использует административную границу `name:en=Astana`; выбираются именованные магазины, офисы, ремесленные предприятия и коммерческие amenities. Результат не является полным реестром компаний города. Из ответа выбирается до 100 карточек, поочерёдно из разных категорий. Объекты одной сети по разным адресам сохраняются отдельно.

Из каталога `backend`:

```sh
go run ./cmd/collect-companies --limit=100 \
  --snapshot=/tmp/astana-source.json --output=/tmp/astana-candidates.json
```

Файлы создаются с правами 0600, существующие файлы не перезаписываются. `--input=/tmp/astana-source.json` повторяет обработку снимка без нового запроса к Overpass. Не включайте выгрузки и отчёты в Git.

Для сохранения в очередь проверки добавьте `--apply` и задайте `DATABASE_URL` runtime-роли закрытым окружением. Требуется миграция `004_company_discovery.sql`. Сетевые проверки завершаются до начала транзакции БД. Повторный запуск обновляет только pending-кандидатов с тем же `(source, external_id)`; рассмотренные записи и ручные правки компаний сохраняются.

Стандартный источник: `https://overpass-api.de/api/interpreter`, настройка оператора — `OVERPASS_URL` с HTTPS. Публичный Overpass используется для разового пилота, не как постоянный backend приложения. Плановый массовый сбор потребует своего экземпляра, выгрузки либо провайдера с подходящими условиями: [правила Overpass](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html).

## Проверка сайта

- Проверяется ссылка `contact:website`, `website` или `url` из карточки.
- Соцсети, справочники и агрегаторы не считаются собственным сайтом.
- DNS и каждое подключение/redirect проверяются на публичный IP; прокси отключён, допускаются только HTTP(S) и порты 80/443. Лимиты: 12 секунд на запрос, 4 redirect, 768 КиБ HTML. При robots-запрете или неопределённом доступе HTML не читается.
- `found` выставляется при совпадении телефона либо названия вместе с адресом/доменом корпоративной почты. Публичные почтовые сервисы исключены из кандидатов. Это эвристика для последующей модерации, не доказательство юридического владения доменом.
- Отсутствующая ссылка, сбой сети, недоступный сайт и неподтверждённая принадлежность дают `needs_review`, с отдельной причиной. Недоступность не означает отсутствие сайта.
- Дополнительные кандидаты формируются бесплатно: из домена email и официальных сайтов `P856` для связанных в OSM `wikidata`, `brand:wikidata`, `operator:wikidata`. Принадлежность бренду/оператору фиксируется отдельно и не считается самостоятельным доказательством принадлежности филиалу. Устаревшие (`deprecated`, с датой окончания `P582`) ссылки исключаются; предпочтительные утверждения имеют приоритет. Другие свойства Wikidata не интерпретируются как URL. Используется только явная связь по QID, без нечёткого сопоставления одноимённых компаний.
- `website_candidates` сохраняет URL, источник, исходную ссылку и scope (`company`, `brand`, `operator`, `inferred`); `website_check.attempts` — результат каждой фактической проверки. Ошибки Wikidata записываются в `discovery_warnings`; они не означают отсутствия сайта. Ответы Wikidata и robots.txt кешируются в пределах последовательного запуска. Запреты robots проверяются для конкретного пути, включая переадресации; Crawl-delay до 10 секунд соблюдается, большие значения откладываются на ручную проверку.
- Платных поисковых адаптеров нет, ключи не требуются. `search_performed=false` означает, что глобального веб-поиска не было. Даже при отсутствии подходящих кандидатов сборщик оставляет `needs_review`, **не выставляет `not_found`**. [Доступ к Wikidata](https://www.wikidata.org/wiki/Wikidata:Data_access), [официальный сайт P856](https://www.wikidata.org/wiki/Property:P856).

## Рассмотрение

Только модератор:

- `GET /api/v1/imports/candidates?status=pending&page=1&limit=20` — карточки и результаты проверки.
- `POST /api/v1/imports/candidates/{id}/review`, JSON `{"decision":"approve","expected_revision":1}` либо `reject`/`link`; актуальную версию брать из ответа карточки.

Одобрение создаёт **скрытую** компанию и категорию. Похожие компании по источнику, имени/адресу или телефону требуют ручной проверки (`409 POSSIBLE_DUPLICATE`); список совпадений доступен в `/imports/candidates/{id}/duplicates`, решение `link` привязывает источник без перезаписи компании. Черновые правки сохраняются отдельно от исходного payload и защищены revision. Все правки, одобрения, привязки и отклонения записываются в журнал. Неподтверждённый website URL не переносится в официальное поле сайта. Публикация — отдельный endpoint модерации. [Полный контракт для кабинета](../../docs/moderation-api.md). Интерфейс реализуется отдельно.

Все карточки содержат `source_url`, исходные tags, дату проверки и атрибуцию `© OpenStreetMap contributors`, ODbL 1.0. Перед публичным показом OSM-карточек необходимо показывать атрибуцию и ссылку на лицензию в интерфейсе; текущий сбор сохраняет их только в закрытую очередь. [Лицензия и атрибуция](https://www.openstreetmap.org/copyright).
